# D2K — Dynamic2Keenetic

D2K наблюдает трафик на Keenetic, измеряет подозрительные соединения, создаёт обход и запоминает рабочее решение. C-runtime, без Zapret/nfqws. TLS 1.2, TLS 1.3, QUIC, IPv4/IPv6 и Telegram-туннель входят в тестовый MVP. Что нового — в разделе [Обновление 06.10.2026](#обновление-06102026).

Поддержать проект:

- TON: `UQA6Y6Mf1Qge2dVSl3_vSqb29SKrhI8VgJtoRBjgp08oB8QY`
- USDT (ERC20): `0xA1D6d7d339f05C1560ecAF0c5CB8c4dc80Dc46A9`
- USDT (TRC20): `TVtWDryrowtb4MYGGtA8Q2yCAei4VFh5g5`

## Установка / обновление — одна команда

Выполняйте **в SSH-терминале Entware на роутере от root**, не на компьютере и не в командной строке KeeneticOS. Основная платформа — Keenetic. На OpenWrt Entware не нужен, команда своя — см. [раздел OpenWrt](#openwrt). Архитектуру установщик определяет автоматически по Entware и `uname` — см. [совместимость](#архитектуры) и [подготовку](#перед-первой-установкой).

```sh
(f=$(mktemp) && curl -fsSL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/necronicle/d2k/main/scripts/install.sh -o "$f" && D2K_REF=main sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Устанавливается ветка **`main`**. Команду достаточно выполнить один раз: дальше D2K обновляется сам из подписанных выпусков на GitHub — ночью 03:00–05:00 по времени роутера или кнопкой «Установить сейчас» в панели (раздел «Обновления»). После установки минуту проверяется, что службы живы; если нет — возвращается прежняя версия. Ночную установку выключает тумблер в панели. Скрипт запускается только после полной успешной загрузки. Перед выполнением можно [посмотреть его код](scripts/install.sh).

## Полное удаление — одна команда

```sh
(f=$(mktemp) && curl -fsSL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/necronicle/d2k/main/scripts/uninstall.sh -o "$f" && sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Удаляются службы, панель, правила D2K, его Instagram DNS-записи, конфигурация, найденные обходы и ключ Telegram. **Изученное состояние будет потеряно.** Чужие правила и DNS-записи не удаляются. [Код удаления](scripts/uninstall.sh).

## Перед первой установкой

1. Установите Entware и включите компонент Keenetic **«Модули ядра подсистемы Netfilter»**. [Официальная инструкция Entware](https://support.keenetic.com/hero-5g/kn-4110/en/20980-installing-the-entware-repository-on-a-usb-drive.html) приведена для ARM64-модели; на сайте выберите свою модель.
2. Подключитесь к **Entware по SSH**, используя его адрес, порт и пароль root. Архитектуру можно посмотреть командами `uname -m` и `opkg print-architecture`.
3. Один раз подготовьте зависимости:

   ```sh
   opkg update && opkg install curl ca-bundle iptables ipset kmod_ndms xtables-addons_legacy openssl-util
   ```

   Команды `ip` и `start-stop-daemon` также должны быть доступны в Entware. Установщик проверяет их, NFQUEUE и connbytes до изменения работающей установки.
4. Остановите z2k, Zapret и другие сервисы, вмешивающиеся в тот же трафик. Затем выполните команду установки выше. Для загрузки нужен доступ к GitHub; при ошибке загрузки скрипт не продолжит установку неполного комплекта.

### OpenWrt

D2K работает на OpenWrt 22.03 и новее (firewall fw4) **без Entware**. Выполняйте в SSH роутера от root. В образе OpenWrt нет `curl`, поэтому команда идёт через `wget`:

```sh
(f=$(mktemp) && wget -q -T 120 -O "$f" https://raw.githubusercontent.com/necronicle/d2k/main/scripts/install.sh && D2K_REF=main sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Удаление:

```sh
(f=$(mktemp) && wget -q -T 120 -O "$f" https://raw.githubusercontent.com/necronicle/d2k/main/scripts/uninstall.sh && sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Проверено в лаборатории (QEMU, ARM64): чистые OpenWrt 24.10.8 и 25.12.5 — установка этой командой, трафик клиента LAN через очередь, `firewall restart`, перезагрузка, повторная установка, удаление; OpenWrt 24.10.8 с прежней установкой через Entware — переход на nftables. На настоящем роутере с OpenWrt пока не проверялось — отзывы нужны. [Замеры](docs/field/2026-10-07-openwrt-native.md).

1. Недостающее установщик ставит сам штатным менеджером пакетов (`apk` в 25.12, `opkg` в 24.10): `curl ca-bundle openssl-util kmod-nft-queue kmod-nfnetlink-queue kmod-nf-conntrack-netlink`. Нужен интернет. iptables, ipset и Entware не нужны.
2. **Место.** D2K с этими пакетами занимает около 15 МБ (замер на ext4). Без USB всё ставится во внутреннюю память: `/opt` — обычный каталог. Если места не хватает, установщик отказывает до каких-либо изменений; тогда подключите USB-накопитель под `/opt`. Обновление держит свои временные файлы (~20 МБ) в RAM, а не на флеше.
3. **Правила** — собственные таблицы nftables `inet d2k`, `inet d2k_rst`, `inet d2k_tg` рядом с таблицей fw4. `firewall restart` и `fw4 reload` их не трогают.
4. **Автозапуск после перезагрузки** — служба OpenWrt `/etc/init.d/d2k` (procd). Установщик ставит и включает её сам; если `/opt` на USB, служба в фоне ждёт его монтирования. Проверка — `/etc/init.d/d2k enabled` и `/etc/init.d/d2k status`; `/etc/init.d/d2k stop` снимает все правила.
5. **Установка через Entware** (прежний способ) обновляется той же командой и сама переходит на nftables: правила iptables D2K снимаются, изученное состояние и ключ Telegram сохраняются. Оставить iptables: `FW_BACKEND=iptables` в `/opt/d2k/config`.
6. OpenWrt 21.02 и старше (fw3, без nftables) идут прежним путём iptables: нужны `iptables`, `ip6tables`, `ipset`, `curl`, `openssl` (Entware или пакеты OpenWrt).
7. Удаление снимает правила, службу и файлы D2K, но не удаляет поставленные пакеты OpenWrt: ими могут пользоваться другие программы.
8. На OpenWrt нет функций, привязанных к KeeneticOS: DNS-записей Instagram/WhatsApp через NDM и разгрузки аппаратного ускорителя PPE. Работу D2K при включённом flow offloading в fw4 (программном и аппаратном) не проверяли: ускоренный поток минует netfilter, и D2K может его не видеть.

## После установки

- D2K запускается автоматически в активном режиме (`MODE=apply`) и подбирает обходы по живому трафику. Начального списка заблокированных сайтов нет; первый поиск может потребовать времени.
- На OpenWrt установщик также создаёт и включает `/etc/init.d/d2k`: служба запускает `S99d2k`, а если `/opt` на USB — сначала в фоне ждёт его. Проверка: `/etc/init.d/d2k enabled` и `/etc/init.d/d2k status`. Удаление снимает эту службу даже с `D2K_KEEP_STATE=1`. На OpenWrt без rc.common/procd установка и обновление продолжаются с предупреждением об отсутствии автозапуска.
- Семейства доменов изучаются автоматически по собственным подтверждённым обходам — и после полного замера, и когда цель подтверждена уже известным планом коробки. После объединения новое совместимое имя сразу получает обход семейства, без отдельного поиска или записи каждого поддомена. TLS 1.2, TLS 1.3, QUIC, ECH и IPv4/IPv6 не смешиваются; реально отличающийся узел может получить своё точечное решение. [Проверка на роутере](docs/field/2026-10-01-learned-domain-families.md).
- Панель доступна **на роутере**: `http://<LAN-адрес-роутера>:8090/`, обычно **http://192.168.1.1:8090/**. Точный адрес напечатает установщик. Никаких команд на компьютере или SSH-туннелей для панели не требуется.
- В панели работают кнопки управления движком и Telegram. У неё **нет пароля**: доступ доверен локальной сети. Не публикуйте порт 8090 в интернете.
- Telegram включается автоматически: роутер создаёт собственный ключ и регистрируется на relay по HTTPS. Вводить общий секрет не нужно; приватный ключ не покидает роутер. Туннель перенаправляет только Telegram TCP, не весь интернет.
- DNS Instagram и WhatsApp Web: роутер получает свежие адреса от собственного C-резолвера d2k на VPS (`https://213.176.74.63.nip.io:9443/resolve`), проверяет диапазоны Meta, доступность узла и его сертификат, затем сохраняет свои записи на роутере (1–2 адреса на имя). Имена: `instagram.com`, `www.`/`graph.`/`api.`/`i.instagram.com`, `instagram.c10r.instagram.com`, `static.`/`scontent.cdninstagram.com`, `static.`/`scontent.xx.fbcdn.net`, `web.`/`www.`/`graph.`/`v.whatsapp.com`, `scontent.`/`static.`/`mmg.`/`pps.whatsapp.net`. Имена точек присутствия CDN заранее не прописываются — это работа обхода. Блокировка имени не считается неисправностью IP: обход SNI подбирает движок отдельно. Первое обновление идёт в фоне сразу после установки (установка его не ждёт; обновление версии не повторяет его, если последнее удалось меньше суток назад), далее — ежедневно в окне **01:00–04:59 по времени роутера** со своей для каждой установки минутой; при неудаче повтор через 30 минут, 1 час, 2 часа… но не позже следующего дня; прежние записи сохраняются. Семейства Instagram, WhatsApp и fbcdn закрепляются независимо (Instagram — только при проверенном `instagram.com`). Каждая своя запись ежедневно проверяется с самого роутера; недоступная снимается, и имя снова решается обычным DNS — даже если VPS недоступен (если не отвечает ни одна запись, это считается сбоем связи роутера, и записи не трогаются). Конфигурация NDM сохраняется только при изменении записей.
- Повторная команда установки обновляет файлы, сохраняя конфигурацию, найденные обходы и ключ Telegram. Ручное отключение туннеля тоже сохраняется.

## Обновление 04.10.2026

В комплект также включён [PR #3](https://github.com/necronicle/d2k/pull/3): TLS 1.3-планы родительского домена наследуются для ECH GREASE.

Дополнение — **голос Discord**: D2K измеряет поздний обрыв собственными IP Discovery-запросами, проверяет STUN-префикс и сохраняет решение для измеренного адреса. При новом подозрении сначала перепроверяет свой подтверждённый приём. Домены и адреса серверов в код не зашиты. Исправлено также применение TCP-template планов к TLS 1.2. Голос подтверждён владельцем на KN-1811; повторный браузерный прогон 19 сайтов для этого дополнения не выполнен. [Замеры и ограничения](docs/field/2026-10-04-discord-udp-late-cut.md).

Обновляется той же командой установки, без потери изученного состояния. `d2kd` и `d2kc` в текущем комплекте говорят по протоколу 13 и ставятся только вместе — установщик делает это сам. Главное:

- **Детекторы обрыва.** Тихий обрыв ответа посреди загрузки (сервер замолкает без RST/FIN) теперь замечается и по TCP, и по QUIC: по повтору FIN без ответа и по счётчикам потока в ядре (ctnetlink) — в том числе когда браузер молча держит замёрзшее соединение. Проверка подозрения повторяет запросы в том же соединении, пока не будет перенесён двойной бюджет коробки, поэтому короткий ответ больше не выдаётся за «проходит как есть».
- **Подбор проверяется объёмом.** План подтверждается, только если поток под ним переносит не меньше двух бюджетов коробки (бюджет измеряется, по умолчанию 25 пакетов). План, снимающий только блок рукопожатия, но режущийся по объёму, закрепляется как частичный обход и заменяется полным, как только тот найдётся. При нескольких привязках имени ставится прошедшая проверку объёмом.
- **Safari и QUIC.** ICMP «время жизни истекло» от собственных приманок с пониженным TTL больше не доходит до клиента — Safari из-за него обрывал соединение QUIC.
- **Chrome и ECH.** Свидетель ECH ищется среди своих подтверждённых привязок прежде случайных имён; без свидетеля планы проверяются повтором собственного ECH-приветствия клиента. Ответ свидетеля 403/404 больше не принимается за антибот.
- **Форма приветствия клиента.** План проверяется и привязывается под форму приветствия самого клиента (TLS 1.2 у приложений и обновлятелей), планы другой формы пробуются как гипотезы.
- **Чистый каталог.** Если замер нашёл только приём, который планом не выражается, поиск продолжается запасными гипотезами вместо «кандидатов нет»; порядок своих планов — по числу успехов, затем по свежести.
- **Блок по адресу** устанавливается одним нейтральным байтом за ~1–2 минуты и честно называется «средствами d2k не обходится», без десятиминутных кругов.
- **Открытый HTTP:** найденный обход применяется к каждому запросу соединения, а не только к первому.
- **Установщик** сам загружает модули netfilter, лежащие в прошивке файлами (`nfnetlink_queue`, `xt_NFQUEUE`, `xt_connbytes`), прежде чем их проверять; при отсутствии модуля называет компонент «Модули ядра подсистемы Netfilter». Панель больше не помечает `D2K_PPE_DEOFFLOAD` как непонятный ключ.

Проверено: полный набор модульных тестов и кросс-сборок; правила файрвола настоящим iptables и сценарии установки в изолированном контейнере; два полных прогона на ARM64-роутере с чистого каталога — 19 сайтов в Safari и Chrome с записью трафика и приложение Discord. Остальные модели по-прежнему требуют полевой проверки.

## Обновление 03.10.2026

Обновляется той же командой установки, без потери изученного состояния. Главное:

- **Подбор из замера, а не перебором.** Для каждой цели сначала проверяются уже подтверждённые планы узнанной коробки (обычно — секунды); полный замер идёт, только если они не подошли. Лишние и повторяющиеся зонды убраны: типичный поиск — единицы-десятки зондов вместо сотен.
- **Честный QUIC.** Ответ засчитывается только на наш настоящий Initial (а не на приманку), каждая попытка — со свежего порта, успех — полный ответ приложения или не меньше 32 КБ. Новые вопросы замера: «безобидная датаграмма перед Initial» и «приветствие, разрезанное на кадры CRYPTO»; план строится из ответов. Если обхода по QUIC нет, браузер честно уходит на TCP.
- **Chrome и GREASE ECH.** Ложный ECH от Chromium больше не уводит поиск в долгую ветку: сразу проверяются готовые планы (Discord, meduza.io и др. — десятки секунд вместо минут).
- **Без потерь пакетов в conntrack.** Пакеты, идущие следом за первым пакетом QUIC/UDP-потока, больше не отбрасываются ядром (раньше каждое новое QUIC-соединение теряло часть приветствия и ~90 мс); задержка первого ClientHello спланированного TCP-потока — с ~14 мс до долей миллисекунды.
- **VPN и маршрутизация Keenetic не ломаются.** Клиент, которого роутер ведёт в VPN или по другому интерфейсу (метки `ip rule` или иной выход), идёт ядром без вмешательства d2k — его трафик не уходит мимо туннеля.
- **Проверка плана не отвергает рабочие обходы** из-за длинных заголовков ответа (WhatsApp Web).
- **Instagram и WhatsApp Web** — 18 имён через собственный C-резолвер d2k на VPS (объединение нескольких DNS-серверов, кэш, лимиты), ежедневное обновление 01:00–04:59 со своей минутой у каждого роутера, самопроверка записей без VPS.
- **Панель:** ход замера (число зондов и текущий вопрос коробке) виден на карточке поиска; новая анимация Telegram-туннеля с переходами между состояниями.
- **Открытый HTTP без прокси.** Весь HTTP (порт 80) снова идёт ядром и ускорителем: прокси `d2khttp` с шестью рабочими потоками на всю сеть убран, при обновлении и удалении снимаются его правила и бинарник. Подмену ответа провайдером (редирект на страницу блокировки, пришедший раньше, чем мог ответить сервер) узнаёт `d2kd` по первым пакетам потока, IPv4 и IPv6. `d2kc` в фоне проверяет HTTPS сайта на том же адресе. Если TLS к 443 проходит и имя стоит в сертификате — или 443 принимает соединение, а TLS обрывается так, как его режет провайдер (тогда HTTPS откроет обычный поиск обхода по трафику браузера), — клиент вместо подмены получает 307 на `https://` тот же адрес. Если 443 закрыт или сертификат на другое имя — подмена проходит как есть, без задержки и без тупика (fast-torrent.ru). Первый заход на заблокированный сайт ещё видит страницу провайдера: проверка начинается по нему; её итог хранится рядом с каталогом и переживает перезапуск. Если HTTPS у сайта нет, подмена становится поводом искать обход самого HTTP-запроса: `d2kc` своим зондом проверяет, воспроизводится ли подмена с роутера, и задаёт коробке короткий ряд вопросов (разрез имени в Host, тот же разрез в обратном порядке, запрос-приманка с испорченной суммой или номером вне окна; сначала — уже найденные свои решения). План принимается, только если собственный зонд дважды подряд получил настоящий ответ сервера, и хранится в `http-plans.txt` рядом с каталогом. HTTP-план применяется только к запросам GET/HEAD с этим Host и никогда — к TLS.
- **Устойчивость:** без таблицы `ip6tables mangle` служба запускается только для IPv4 вместо отказа; широковещательный и групповой трафик не попадает в очередь; правила RST за зондами не остаются; часы измерителя 64-битные (на MIPS больше нет сбоя после ~25 дней работы); `stop` и удаление убирают всё своё.

Проверено: полный набор модульных тестов и кросс-сборок, правила файрвола настоящим iptables и шесть сценариев установки/обновления/удаления в изолированном контейнере, работа на ARM64-роутере (YouTube по HTTP/3, WhatsApp Web, Discord, meduza.io, rutracker). Остальные модели по-прежнему требуют полевой проверки.

### Обновление IPv6

Добавлен нативный IPv6-путь для TLS 1.2, TLS 1.3 и QUIC: перехват, замер,
подбор, применение и сохранение обходов. IPv4 и IPv6 имеют отдельные
подтверждения; отключать IPv6 или принудительно переводить QUIC на TCP не нужно.
Обновление — той же командой установки выше, без удаления изученного состояния.
Для правил IPv6 требуется доступный `ip6tables` с NFQUEUE и connbytes;
неполный набор правил считается ошибкой, а не рабочей поддержкой IPv6.
Если таблицы `ip6tables mangle` в прошивке нет совсем (нет компонента IPv6 или
модуля `ip6table_mangle`), служба запускается только для IPv4 и прямо пишет
об этом при запуске и в `S99d2k status`; IPv6-трафик тогда идёт без d2k.

Полевые проверки на ARM64-роутере: YouTube отвечает по IPv6 с принудительными
TLS 1.2 и TLS 1.3 (`curl`), HTTP/3 — отдельным клиентом на основе C-верификатора
D2K. Все три обхода сохранились и повторно сработали после перезапуска движка.
Google отвечает по IPv4 и IPv6. Независимые HTTP/3-клиент и сервер
проверены в изолированном Linux-стенде. На Android проверено видео YouTube
в 720p60 через Wi-Fi: QUIC к видеосерверу по IPv6, повторное открытие и
воспроизведение с 8-й минуты после перезапуска движка. Автопоиск для
`i.ytimg.com` подтвердил и сохранил IPv6/TLS-план существующей коробки.
[Подробности и границы проверки](docs/field/2026-09-29-ipv6-phone.md).
Другие модели роутеров требуют полевой проверки.

### Команды

```sh
/opt/etc/init.d/S99d2k status   # состояние компонентов
/opt/etc/init.d/S99d2k stop     # остановить D2K и снять его правила
/opt/etc/init.d/S99d2k start    # снова запустить
/opt/etc/init.d/S99d2k restart  # перезапустить
```

Если после включения появились проблемы с сетью, сначала выполните `stop`. Настройки находятся в `/opt/d2k/config`, журналы — в `/opt/d2k/log/`.

Изученное состояние лежит в `/opt/d2k/state/` тремя файлами, и «начать с чистого листа» значит убрать все три (отдельной команды сброса нет; полное удаление без `D2K_KEEP_STATE=1` убирает их вместе с остальным):

- `catalog.json` — коробки и найденные обходы TLS/QUIC/голоса;
- `https-cache.txt` — проверка HTTPS имён, на которые провайдер вставлял страницу блокировки (по ней d2k переводит такой HTTP на https);
- `http-plans.txt` — найденные обходы открытого HTTP (имена без HTTPS).

```sh
/opt/etc/init.d/S99d2k stop
rm -f /opt/d2k/state/catalog.json /opt/d2k/state/https-cache.txt /opt/d2k/state/http-plans.txt
/opt/etc/init.d/S99d2k start
```

Для Instagram и WhatsApp Web:

```sh
/opt/d2k/d2k-instagram-dns.sh refresh       # обновить сейчас (до нескольких минут)
cat /opt/d2k/state/instagram-ip-hosts.tsv  # только записи, принадлежащие D2K
tail -n 30 /opt/d2k/log/instagram-dns.log
```

Ошибка DNS-обновления не означает автоматически, что VPS недоступен: журнал различает отказ запроса, недоверенный адрес/сертификат и ошибку сохранения на роутере. Не отключайте проверку сертификатов ради успешного статуса.

Чтобы удалить программу, но оставить конфигурацию и изученное состояние, добавьте `D2K_KEEP_STATE=1` перед командой `sh "$f"` в строке удаления. Обычная команда выше удаляет всё состояние D2K.

## Архитектуры

Для каждой цели собирается полный статический C-комплект: движок, контроллер, панель и Telegram. Отдельная установка OpenSSL-библиотек для этих бинарников не нужна; `openssl-util` и CA-сертификаты нужны установочным скриптам.

| Цель | Требования |
| --- | --- |
| ARM64 | AArch64 |
| ARM32 | ARMv7 и новее, little-endian, EABI, VFPv3 |
| MIPS / MIPSEL | MIPS32, big-/little-endian соответственно, soft-float |
| MIPS64EL | MIPS64, little-endian, N64 ABI, **нужен FPU** |
| x86 / x86-64 | i686 / x86-64 |
| PPC64 | 64-битный PowerPC, big-endian |
| RISC-V64 | RV64GC |

Для MIPS64EL установщик дополнительно проверяет наличие FPU и отказывается менять установку, если подтвердить его не удалось. Нативный MIPS64EL без FPU пока не поддерживается.

Проверки пакетов: запуск всех 36 бинарников под QEMU, отсутствие динамических зависимостей, криптография, QUIC-пакеты, разбор планов, OpenSSL и Telegram-сессии. MIPS32-сессии дополнительно проверены на эмулируемом CPU без FPU. Изолированный ARM64-тест проходит установку, обновление, безопасный отказ, остановку/запуск и полное удаление.

Это тестовые пакеты, **не подтверждение совместимости со всеми моделями**. Реальная установка ранее проверялась на ARM64; остальные устройства требуют полевых тестов. Эмуляция проверяет запуск и переносимость, но не драйверы Netfilter, NDM и производительность конкретного роутера. На Keenetic нужны Entware, NFQUEUE, connbytes и ipset; на OpenWrt 22.03+ — nftables с очередью (`kmod-nft-queue`), всё недостающее ставит установщик. Lexra, ARMv5/ARMv6 и 32-битный PPC не поддерживаются; MIPS64 с 32-битным Entware получает пакет MIPSEL/MIPS согласно ABI Entware. Неизвестная архитектура вызывает явный отказ до остановки старой службы.

## Для разработчиков

D2K вырос из переноса «Поиска по домену» z2k на C и с 03.10.2026 развивается как самостоятельный проект: мерило изменений — полевые замеры, а не совпадение с донором. Полные требования: [D2K_SPEC.md](D2K_SPEC.md) (начните с §0); история и ограничения: [D2K_HANDOFF.md](D2K_HANDOFF.md). Принятый владельцем MVP не означает завершение всех пунктов полного ТЗ, включая STUN и безымянный IP-трафик.

```sh
sh scripts/check.sh
make -C telegram test
make -C panel test
make -C relay-enroll test
sh scripts/lab-install.sh  # изолированная установка/удаление; нужен Docker
```

На роутере работают C-процессы `d2kd`, `d2kc`, `d2kpanel` и `d2ktg`. Серверный Telegram relay — существующий внешний сервис z2k; его Go-runtime не устанавливается на роутер. Регистрация роутеров и резолвер Instagram/WhatsApp — собственный C-сервис d2k на VPS (`relay-enroll`). Для сборки нужны make, Perl, git и Zig **0.16.0**; для MIPS64EL используется **0.14.1**, поскольку 0.16.0 не линкует полный runtime этой цели. OpenSSL закреплён по commit.

```sh
ZIG_MIPS64EL=/path/to/zig-0.14.1 sh scripts/build-router.sh
# Или только нужные пакеты:
ARCHES="arm64 mipsel" sh scripts/build-router.sh
# Сборка существующих регрессий под те же CPU/ABI:
ZIG_MIPS64EL=/path/to/zig-0.14.1 sh scripts/build-router-tests.sh
# На Linux с qemu-user и binutils:
sh scripts/check-router-builds.sh
```

### Выпуск и автообновление

Пошагово, с правилами и действиями при сбоях: [RELEASING.md](RELEASING.md).

Выпуск — GitHub Actions → **D2K release** → *Run workflow* на `main`: сборка девяти арок, проверки под QEMU, архив на каждую арку и подписанный `latest.json`. Роутеры проверяют подпись закреплённым ключом и ночью 03:00–05:00 (или по кнопке в панели) ставят выпуск его же установщиком; через минуту проверки остаётся только новая версия, при сбое возвращается прежняя. Закрытый ключ подписи в репозиторий не попадает; открытый закреплён в `files/d2k-update.sh`.
