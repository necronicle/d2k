# d2k — Dynamic2Keenetic

Обход DPI для роутеров Keenetic, который **ничего не знает заранее**.

Без поставляемых списков заблокированных доменов. Без предварительного
объявления сайтов заблокированными. Пользователь пользуется интернетом, d2k
наблюдает; когда соединение не проходит, d2k измеряет поведение блокировки,
подбирает преобразование и запоминает то, что сработало.

Полное описание архитектуры и принципов — в [D2K_HANDOFF.md](D2K_HANDOFF.md).
Здесь только то, что нужно, чтобы понять и запустить.

## Что он делает

1. Смотрит на транзитные соединения. Узнаёт TLS, вынимает имя цели.
2. Замечает подозрительное: подделанный сброс, повтор приветствия, молчание
   в ответ на приветствие.
3. Стучится в цель **сам**, повторяя форму приветствия клиента, и перебирает
   преобразования, пока обмен не пойдёт.
4. Сработавшее — записывает: модель поведения коробки, план и привязку цели.
   Не сработавшее — **не записывает вообще ничего**.

Последнее не оговорка, а правило. «Сервер лежит», «блокировка по IP»,
«перебор исчерпан» — для d2k это один и тот же исход: решения нет, записи
нет. Линия, маршрут и сам DPI меняются; вчерашний отказ завтра не значит
ничего, а сохранённый будет мешать честной повторной попытке.

## Как это выглядит на живой линии

Клиент сходил один раз и получил отказ. Дальше без его участия:

```
подозрение по linkedin.com (сброс в ответ на приветствие): начат поиск
  примета: rst ttl=126 (сервер 122) tos=0x88 ipid=54321
по linkedin.com пробую plan-b08307c3, попытка 1
по linkedin.com поймана форма приветствия: 322 байт
по linkedin.com стучусь сам: форма клиента -> 130.211.32.14:443
по linkedin.com обмен пошёл: заведена коробка box-4c6254bf
```

От подозрения до применённого плана — 77 мс. Дальше цель открывается сразу,
а следующая цель с тем же поведением коробку **узнаёт** и новый подбор не
запускает.

## Устройство

Два процесса, и это намеренно: падение планировщика не должно ронять разбор
пакетов.

| | язык | что делает |
|---|---|---|
| `d2kd` | C | видит пакеты: NFQUEUE, учёт потоков, разбор TLS, исполнение планов |
| `d2k` | Go | каталог коробок, подбор, зонды, панель |

Язык выбран замером, а не вкусом: `docs/field/2026-09-05-stage0-implementations.md`.
C и Rust по скорости неразличимы, решил тулчейн — у `rustup` нет ни одной
MIPS-цели. Go в датапате выбывает по ресурсам: 22 % процессора против 15 и
5,1 МБ памяти против 224 КиБ.

На пакетном пути нет плавающей арифметики: MIPS-коробки идут без
сопроцессора.

## Состояние

Работает на устройстве и проверено на живой линии: этапы 0, A, B, C, D и
частично E. Чего ещё нет — QUIC, STUN, IPv6, обнаружение поздних обрывов,
автообновление. Список ведётся в [D2K_HANDOFF.md](D2K_HANDOFF.md), раздел 0.

**Готовой команды установки нет.** Публиковать её до проверки установки с
чистого состояния нельзя, и это правило продукта, а не осторожность.

## Сборка и проверка

```sh
sh scripts/check.sh          # всё: формат, vet, тесты C и Go, санитайзеры,
                             # чужой компилятор, кросс-сборка, shellcheck
make -C datapath d2kd-aarch64   # служба датапата под роутер
sh scripts/build.sh             # d2k под девять арок
```

`scripts/check.sh` — единственный вход в проверку. Звать его надо через `&&`:
точка с запятой пропускает красный вердикт дальше, и это уже стоило коммита
с непроходящим форматом.

## Полевой прогон

```sh
D2K_ROUTER=… D2K_SSH_PASS=… D2K_MODE=apply D2K_MARK=45 \
D2K_SRC=<адрес клиента> D2K_LEARN=1 \
sh scripts/field-observe.sh
```

Скрипт собирает, доставляет, ставит правила, поднимает службу и контроллер,
собирает вывод и **убирает за собой** — правила снимаются по жетону запуска,
каталог и журналы забираются, временное на роутере удаляется. Ничего не
пишется на флеш-накопитель.

Опыт обязан быть узким: без `D2K_SRC` или `D2K_DST` активный режим не
запускается. На роутере живут чужие устройства, и десинк всего 443-го порта —
не эксперимент, а авария.

## Происхождение

Донор опыта и части решений — [z2k](https://github.com/necronicle/z2k),
MIT, тот же автор. Перенесены не исходники, а измеренное: рабочее плечо
записано форматом Plan, ошибки донора перечислены в D2K_HANDOFF §6.2 и
исправлены, а не унаследованы.

nfqws и Lua-библиотеки Zapret не являются компонентами d2k.
