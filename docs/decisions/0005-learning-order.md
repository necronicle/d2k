# Возврат к исходному циклу обучения — 12.09.2026

Статус: первая локальная вертикаль после ревью. **Не готовый MVP и не
разрешение раскатывать промежуточный контроллер на весь трафик.**

## Основа, которую сохраняем

Измеритель «Стратегии по доменам» / `z2k-detect` — основа исследовательской
части d2k, а не только источник строк конфигурации. Его вопросы, воздействия
и накопленные исправления развиваем вокруг собственного исполнителя Plan.
Ошибки критерия успеха донора или текущего переноса не являются контрактом.
Код nfqws/nfqws2 не возвращается в исполнение.

## Реализованная последовательность

1. Подозрение даёт пассивные признаки и кандидатов моделей DPI.
2. Из совместимых моделей собирается ограниченная очередь готовых планов,
   упорядоченная по положительным результатам. Одинаковые тексты планов не
   испытываются повторно в этой очереди.
3. До исчерпания очереди **не вызываются** проба на объём, дерево вердиктов,
   опрос свойств или синтез новых планов.
4. Когда очередь не помогла, пробный план снимается; начинается ровно один
   исследовательский проход в пределах текущей задачи.
5. `INCONCLUSIVE` и `FLAKY` не запрещают сборку ограниченного набора
   кандидатов. Отсутствие диагноза не равно отсутствию решения. `CLEAR` и
   отсутствие транспорта пока завершают этот исследовательский проход.
6. При окончательной неудаче отправляется команда снятия установленного
   этой задачей пробного плана. Подтверждённые записи других целей не меняются.

Готовая очередь и новая очередь имеют отдельные места в общем бюджете:
`2 * SCHED_MAX_PLANS + D2K_PROPS_QUESTIONS`. Это предел попыток установки
кандидатов/вопросов, **не полный счётчик сетевых соединений** классификатора.
Полный учёт затрат всех зондов ещё требуется.

## Идентичность коробки

Первое пассивное совпадение не останавливает просмотр каталога: планы могут
прийти от нескольких совместимых моделей. Источник хранится у кандидата.
После провала готовой очереди новый синтез не наследует ID первой модели.
Новая запись выводит ID из пассивного отпечатка и найденного плана.

Это консервативное разделение, **не законченное распознавание коробок**.
Активные свойства ещё не сохраняются в отпечатке. Если один и тот же план
принадлежит нескольким совместимым моделям, текущая дедупликация оставляет
одного владельца; успешный план сам по себе не доказывает уникальность этого
владельца. Это отдельная незакрытая часть замечания 5.

## Что эта вертикаль намеренно НЕ объявляет исправленным

- TLS type 23 по-прежнему ошибочно участвует в подтверждении. Поэтому
  результаты текущего `on_exchange` нельзя считать доказательством работы
  приложения; старые записи каталога не становятся более достоверными от
  изменения порядка поиска.
- Обычный кандидат пока ждёт трафика пользователя. Автономное испытание и
  его связь с точным потоком/версией плана ещё предстоят.
- Контекст привязки пока не разделяет ClientHello, адрес/семейство и выход.
- Фиксированный контроль ещё используется диагностикой; убран его статус
  обязательного допуска к синтезу, но корректность контроля не исправлена.
- Снятие пробного плана — отправка DEL_NAME, не подтверждённая транзакция.
  При неисправной управляющей связи гарантии исполнения этой команды нет.

## Следующая вертикаль: проверка без ложного успеха

До новой полевой приёмки нужно связать в один цикл:

1. Подозрение и короткое распознавание → известные планы, затем исследование.
2. Самостоятельное ограниченное обращение на тот же адрес, порт и путь.
3. Доказательство применения **данного** плана к **данному** потоку.
4. Полноценная TLS/прикладная проверка; ServerHello и внешний type 23 дают
   только предварительные наблюдения. Повтор снятого ClientHello не даёт
   проверяющему секретов клиента для завершения исходного рукопожатия.
5. Сохранение с явным контекстом фактически проверенного клиента/протокола,
   без переноса успеха собственного зонда на произвольную форму ClientHello.
6. Автономная смена кандидата при неудаче и безопасная уборка временного плана.

Нужны регрессии: TLS 1.3 server flight без HTTP не сохраняется; чужой поток
или старая версия плана не подтверждают попытку; без повторного обращения
пользователя очередь продвигается; TLS 1.2 и TLS 1.3 не перезаписываются;
успешное повторное использование не вызывает новый синтез.
