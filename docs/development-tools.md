## Serena и обновление индекса

MCP `serena` запускается локально через `/Users/mark/.local/bin/serena`,
с контекстом `codex` и явным проектом `/Library/Zapret2/d2k`, без dashboard/GUI.
Это пользовательская настройка Codex: для другого проекта нужно явно
активировать его или изменить запуск, а не считать D2K текущим автоматически.

Из корня D2K:

```sh
sh scripts/refresh-code-index.sh
serena project index .
serena project health-check .
```

Генератор использует `compiledb` и `jq`, сухой запуск `make -B all check`
в каждом компоненте; сами сборка и тесты не выполняются. Текущий результат:
102 записи (core 51, datapath 38, detect 13), не полная Linux cross database.
Некоторые файлы/варианты получают выведенную clangd команду; не обещать полноту
индекса макросов, Linux-веток, отдельных test-only определений и spike-кода.
После изменения флагов/новых файлов обновить базу и перезапустить MCP/LSP.

`compile_commands.json`, `.serena/` и `.cache/clangd/` локальные и исключены
из git. При первом индексировании были сообщения IncludeCleaner о неразрешённых
путях и предупреждение очистки process group; health-check и проверка MCP после
этого завершились успешно. Это не заменяет настоящую компиляцию и тесты.

## Границы выполненной настройки

Исходники продукта, чужие изменения, службы роутера и firewall не менялись.
Развёртывание, security/fuzz-кампании и полевые опыты не запускались.
Docker сообщает `linux aarch64`, но новый сетевой стенд здесь не проверялся.
Ничего не закоммичено: в дереве остаются незакоммиченные изменения коллеги.

Не публиковать полный `codex mcp list`, конфиг или окружение: существующие
серверы могут содержать ключи прямо в аргументах. При проверке старой настройки
Context7 такой ключ попал в локальный журнал; пользователю рекомендован его
перевыпуск. В эту документацию значение не переносить.
