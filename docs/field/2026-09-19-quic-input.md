# QUIC: восстановление входа в оригинальный поиск

Продолжение после `ca5e6fb`, ветка `classify-core`. Цель — MVP по D2K_SPEC,
не новый алгоритм. Роутер в этой итерации не изменялся.

## Исправлено: восемь кадров вместо всех байтов

Полевой отчёт `2026-09-19-quic-field.md` зафиксировал много CRYPTO-кадров
в обратном порядке и две Initial-датаграммы клиента. `core/quic.c` сохранял
только первые восемь кадров, остальные молча отбрасывал. Даже полностью
доступный ClientHello внутри одной датаграммы мог не дать SNI.

Регрессия берёт ClientHello из RFC-вектора, разбивает на однобайтовые кадры
и шифрует существующим кодировщиком. Две версии (v1/v2) × два порядка кадров.
До исправления — 8 ожидаемых падений SNI/полного ClientHello. После — 0.
Повреждённый AEAD-тег по-прежнему отвергается. Проверка кодировщика остаётся
в независимых RFC-векторах `test_quicwire`, новый тест проверяет сборку кадров.

Теперь каждый кадр кладёт байты по смещению, а битовая карта помнит наличие.
Ограничения — прежние 1500 байт входа/собираемого сообщения, без выделений
и без массива по числу кадров. Выдаётся только непрерывный префикс от нуля.
Пропуски не заполняются; неизвестный хвост останавливает разбор как раньше.

Проверено: `test_quic`, `test_quichello`, `test_quicprobe`, `test_quic_arms`,
полный `make -C datapath check` — код 0. `test_quic` из исходников под
ASan/UBSan — код 0; этот же тест компилируется/линкуется для ARM64 musl и
MIPS glibc. Это не полевой прогон и не полная приёмка QUIC.

## Холодный старт: исходный запрет снят

`quicprobe.Run/buildInitial` донора создаёт собственный Initial без снимка.
`fill_hellos` теперь при отсутствии снимка использует уже существующий
`d2k_qc_first_initial`: QUIC v1, TLS 1.3, ALPN h3, собственные случайные CID
и ключи, датаграмма 1200 байт. Контроль переименовывается из этого входа.
`trig_snapped` не выставляется: источник остаётся PROFILE. Готовые планы
коробки по-прежнему проверяются до нового вопросника, без требования снимка.

Регрессия до изменения: четыре падения — вопросник не вызван без снимка,
нет Initial цели/контроля, нет явного обозначения собственного входа.
Один замер без подтверждения не создаёт привязку. Поздний SHAPE не меняет
байты уже идущего опыта.

Проверено: `make -C core test_sched && core/test_sched` (запуск из `core`)
— все проверки прошли; сборка `test_sched.c` со всеми `$(SRC)` под
ASan/UBSan и запуск — код 0. Изменённый `sched.c` компилируется для
ARM64 musl и MIPS glibc. Логи: `/tmp/d2k-quic-cold-{red,green,proof}-20260919.log`.
Нового полевого подтверждения нет.

**Это устранение запрета, не завершённое соответствие формы оригиналу.**
У C-зонда подтверждения один cipher suite, собственные порядок расширений
и transport parameters (1452/16 потоков против 1472/100 у донора), длина PN
выбирается кодировщиком, а донор задаёт 4. Следующий шаг — исходный
измерительный ClientHello/Initial оригинала в C с тестом соответствия;
не менять ради этого отдельное настоящее рукопожатие зонда подтверждения.
Также фиксированный `disk.rzd.ru` в C не равен случайному нейтральному имени
`z%x.example.com` оригинала: контроль надо сверить, а не объявлять эквивалентным.

## Следующие разрывы (ещё открыты)

1. Между UDP-датаграммами состояния сборки пока нет. Извлечённое имя не
   разрешает выдать последнюю половину приветствия за полный снимок, а
   склейка датаграмм меняет измеряемую форму. Нужны ограниченная сборка,
   принадлежность соединению и явное сохранение границы наблюдённого входа.
2. QUIC-снимок в общем кэше не связан с именем; SHAPE во время ASKING/VERIFY
   не приводит к перемеру после окончания опыта (TCP уже умеет).
   Нужны полный вход, принадлежность цели и повтор без подмены текущего опыта.
   Подключение собственного Initial не закрывает соответствие его формы
   оригиналу — см. выше.
3. Протокольное подтверждение, адресный поиск, voice и полный цикл коробок
   остаются открытыми — см. актуальное начало MVP_CHECKLIST.
