# 16.09.2026 — провод, единственный поиск и неизменяемый вход

База `2257b8c`, ветка `classify-core`. Требования: [D2K_SPEC](../../D2K_SPEC.md).
Это продолжение пункта 1 и локальное закрытие пункта 2
[чеклиста](../../MVP_CHECKLIST.md), **не готовый MVP**.

## Исправлено

- Для измеренных TCP-планов введён `wire detect-tcp-v1` (REC_WIRE `0x0109`,
  minexec 4). Заголовки повторяют C-порт отправителя оригинала: TSval=1,
  XOR суммы с `0xbeef` и нулевой случай `0x1234`, TTL=64 по умолчанию,
  window=65535, DF=0, случайный IPv4 ID либо ноль по флагу.
  Старые планы сохраняют прежнюю семантику. UDP эту директиву не принимает.
- Реальные `detect/raw.c:build_ipv4_tcp` и `datapath/wire.c:d2k_wire_build`
  сравниваются в `detect/test_raw.c` целиком на 32 сочетаниях флагов,
  TTL и seqshift. Нормализуется только случайный IPv4 ID и зависимая сумма
  IPv4; TCP-сумма, опции и полезная нагрузка сравниваются без нормализации.
  Это проверка кодировщиков, не обещание, что Linux IP_HDRINCL не меняет ID.
- `payload-pad64` хранит точный префикс в base64, без увеличения слота плана.
  Измеренная приманка 2048 байт с семью повторами и перекрытием помещается
  в текстовые 4096 байт. Декодер отвергает мусор, неправильное и неканоническое
  заполнение; на провод идут те же байты, что до кодирования.
- `owns_search` отделяет результат полного перенесённого инструмента от
  старого ответа «только класс». После оригинального поиска не запускаются
  старые вопросы и второй fallback d2k. PREFIX/WHOLE сохраняют найденный
  `split_pos` и исходный `write_gap_ms`; отсутствие poison-arm не теряет split.
  Собственные резервные ветки оригинала не удалены.
- Исправлен реальный TCP-верификатор: использует зарезервированный сокет,
  по порту которого установлен изолированный план, а не открывает второй.
  Регрессия проверяет дескриптор и порт настоящим loopback-соединением.
- Рабочий поток получает свою копию trigger/control; дескриптор опыта
  передаётся ему с владением. Поздний SHAPE не меняет ни память измерителя,
  ни контекст сборки/подтверждения его результата. Целый снимок сохраняется
  для следующего поиска; ожидающая снимка задача получает его до старта.
- Наличие SNI в первом TCP-сегменте больше не означает «полный вход»:
  `d2k_hello_complete` проверяет целую однозаписную оболочку ClientHello.
  Неполный снимок не заменяет вход и не сохраняется как шаблон.
  Это **не** реализация TCP-reassembly и не полная проверка семантики TLS.

## Проверки

Пройдены `make -C datapath san cross`, `make -C detect check cross`,
`make -C core cross`, `make -C core test-measured san-measured`.
Проверки планировщика включают четыре исхода полного инструмента
(OPAQUE без находки, PREFIX, WHOLE, найденный poison-arm): ровно один поиск,
нет второго перебора. Отдельно проверены владение сокетом и входом,
запрет использования обрывка и использование полного кэшированного снимка.
Финальные команды после последующих изменений фиксировать дополнительно.

## Стенды: красные результаты не скрывать

Исправлена сборка `scripts/lab-censor.sh` (устаревшие списки исходников).
Адрес TLS-сервера перенесён с loopback 127.0.0.1 на локальный alias
10.203.0.1: оригинал намеренно отказывает loopback. Старый зелёный прогон,
который прошёл через второй самодельный fallback, не доказывал перенос.

Свежий прогон на 10.203.0.1 нашёл **disorder** оригинальным инструментом
для обеих лабораторных целей. Применений было **0**, клиент не прошёл,
подтверждённого каталога нет. При входе поиска 1544/1555 байт приходил
SHAPE 1448 байт; Plan отказывал проверочному пакету как несовместимому.
Этот прогон был до последней правки, замораживающей контекст всей задачи.

`scripts/lab-transit.sh` также красный: клиент за NAT — 0/3; цензор жив,
207 пакетов снято по имени. До конца окна наблюдения поиск не завершился.
В этом стенде DNS возвращал разные IP клиенту на разных обращениях;
закрепить один адрес для сопоставимых опытов. Не объявлять причину задержки
установленной только по этим логам.

## Продолжить здесь

1. Воспроизвести отказ применения с неизменяемым входом. У измерителя,
   собственного TLS-зонда и клиента различаются длины/SNI-координаты;
   проверка `input` правильно отвергает несовместимость, но её одной
   недостаточно для реализации обхода. **Не снимать проверку вслепую.**
2. Переносить параметризацию исходного воздействия, а не привязывать любую
   стратегию навечно к одному буквальному смещению. Например, чистый
   disorder исходно вычисляет рез из SNI каждого входа; точные зависимости
   от захваченных байтов у fake/seqovl необходимо сохранять отдельно.
   Проверить соответствие на нескольких разных входах и реальные пакеты.
3. Довести наблюдение составного ClientHello и его исполнение. Отказ от
   неполного снимка устраняет ложный опыт, но не добавляет поддержку клиента.
   `MAX_PKT/copy_range=1600` и предел входа 2048 остаются ограничениями.
4. Подтвердить сквозную вертикаль за NAT. Не менять лабораторный критерий
   на «собственный зонд ответил» и не выдавать короткое приветствие за
   поддержку длинного. TLS 1.2 всё ещё нельзя подтверждать TLS 1.3.
5. SYN-data/OOB/MD5 пока явно отвергаются (добавлены регрессии адаптера).
   QUIC/voice-STUN и полный C-runtime панели остаются отдельными долгами ТЗ.
