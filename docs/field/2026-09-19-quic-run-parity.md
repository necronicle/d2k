## Воспроизведение и изменение

Новый [стенд](../../tests/quic-run/README.md) запускает НЕ переписанную модель
вердиктов, а неизменённый Go `Run` с настоящими UDP-сокетами. C измеряет
эквивалентный локальный сценарий. Сначала проверяется ожидаемая реакция
донора, затем совпадение C; сравниваются вердикт и число отправленных зондов.

Красный прогон выявил пять отличий:

- ICMP при молчащем контроле: C INCONCLUSIVE вместо NO_QUIC.
- Молчащие Initial и VN: C INCONCLUSIVE вместо ADDRESS.
- Ответ VN при молчащем контроле: C добавлял прямой зонд, 9 отправок вместо 6.
- Успех прямого зонда: C добавлял два повтора из TCP-пути, 8 вместо 6.
- Один ответ контроля из трёх: C прекращал поиск как FLAKY, оригинал продолжает
  прямым зондом. Для контроля достаточно хотя бы одного ответа; прямому зонду
  для CLEAR по-прежнему нужны все исходные повторы.

Эти ветки `core/quicprobe.c:d2k_quic_classify` исправлены. Причины не выдают
неотправленный прямой зонд за молчащий и не утверждают локализацию ICMP/DPI.
Исход прибора сохранён отдельно от границ доказательства. Защита от локального
сбоя отправки и неподтверждённой метки обхода не удалялась.

Ожидания старых C-тестов изменены на основании независимого красного прогона,
а не ради зелёного набора. Проверка обвязки дополнена: CLEAR/ADDRESS/NO_QUIC
не должны вызывать подбор приёма, зонд подтверждения или создавать коробку.

## Что это НЕ закрывает — следующий приоритет

1. `ask_worker` по-прежнему вызывает arm hook ПОСЛЕ всего classify. Оригинал:
   base → direct → residual → **askArms → askProperties**, общий `addrPool`.
2. `core/props.c:qa_confirm` безусловно требует свежий второй адрес. В оригинале
   `addrPool.take` возвращает тот же pinned IP, пока residual не обнаружен.
   Поэтому существующий C-подбор отбрасывает даже найденное воздействие на
   одноадресной цели. Исправлять надо общий контекст/политику адресов и порядок,
   не просто разрешать любой повтор на загрязнённом адресе.
3. Сам `d2k_quic_pick_arm` ещё не эквивалентен `askArms`: оригинальные пять
   гипотез начинаются `quic5`, `quic_google`, `quic_rutracker`, внутренний
   `fake_default_quic`, 16 нулей; C начинает собственной переименованной
   приманкой. Внутренние данные оригинала разрешены ТЗ, их нельзя удалять как
   «готовый пользовательский пул». Сохранить исходные измерения/порядок,
   проверить точные байты и семантику исполнителя.
4. Сверить свежесть CID/ключей/нейтрального имени каждого повторного опыта:
   оригинал вызывает `buildInitial` для каждой попытки, а C получает готовый
   снимок на серию. Здесь ещё нет доказательства соответствия на проводе.
5. Ветка residual, остальные вопросы, голос/STUN, сборка входа из нескольких
   датаграмм, подтверждение UDP и жизненный цикл коробок остаются открытыми.

Не закрывать пункт 4/MVP по шести терминальным сценариям: полноценная ветка
с поиском воздействия ещё требует переноса. Эти тесты не показывают доступ
к приложению и не заменяют полевую приёмку.
