# QUIC: исходная фрагментация через Plan и настоящий Linux sender

Продолжение после `3f1d3a3`, ветка `classify-core`, начальное дерево чистое.
Правки этого этапа — текущий исполнитель. Роутер и его службы не трогались.
Это checkpoint до MVP, не выпуск и не объявление полной QUIC-вертикали.
Донор HEAD повторно проверен: `10c6127b744bd3b8631bd381b20c496e06dc0423`;
`internal/quicprobe` не отличается от pin ТЗ. Донор не редактировался.

## Что перенесено

Оригинал: `quicprobe/questions.go:compose` и `fragArmLine` закреплённого
`e9a3913`. Найденные fake и fragment **комбинируются**, fragment-only не
получает выдуманной приманки. Оригинал после фрагментов снимается. Результат
с неизвестной формой или неподтверждённым выживанием фрагментов отвергается.

| Переход | Реализация | Проверка |
| --- | --- | --- |
| Результат askArms → Plan | `core/compose.c`, `sched.c` | fragment-only, fake+fragment, точные bytes/copies/TTL; каталог сохраняет форму |
| Текст → TLV → actions | `plantlv.c`, `plan_parse.c`, `plan_apply.c` | `ipfrag 1..4`, REC_IPFRAG=0x010c, minexec=7, транспорт UDP, отказ противоречивых операций |
| Actions → IPv4 | `session.c` + общий `core/ipfrag.c` | один логический PAYLOAD → 2/3 настоящих IP-фрагмента, полная UDP checksum |
| IPv4 → настоящий провод | `raw.c`, `d2kd.c` | отдельный NODEFRAG socket, предварительная проверка сокета до любых fake |

Старая версия исполнителя откажет по minexec, а не исполнит fake-only.
Один PAYLOAD остаётся целой UDP-датаграммой: запрет превращать куски QUIC в
независимые UDP-пакеты не ослаблен. Счёт результата/подтверждений — по
фактическим пакетам после развёртки. `first_payload` указывает на первый
реальный IP-фрагмент. DROP и DONE различаются: до подтверждения всех посылок
и вердикта оригинала DONE нет.

Общий builder получил вариант с TTL/TOS клиентского пакета. Измерительная
обёртка сохраняет исходные 64/0 и прежние байты. Случайный начальный IP ID и
ненулевой счётчик принадлежат сессии, а не копируются из часто нулевого ID
клиентских DF-пакетов. IPv4 options пока отвергаются, не теряются молча.

## Выявленный дефект: conntrack отменяет воздействие

До изменения raw sender реальный Linux с включённым conntrack давал:
pos8 — 2 пакета; reverse pos8 — 2, **но другой порядок**; обе overlap-формы —
**0 пакетов**. Сборщик при этом проходил побайтовые тесты. Conntrack собирал
фрагменты раньше их выхода, а затем обычная отправка меняла воздействие.

Для фрагментов теперь отдельный raw socket с обязательным `IP_NODEFRAG`.
Обычный raw socket не меняется. Это соответствует проверенной ветке
[IPv4 defrag](https://raw.githubusercontent.com/torvalds/linux/master/net/ipv4/netfilter/nf_defrag_ipv4.c).
Отказ настройки/mark не переключает отправку на обычный сокет.

**NAT у фрагментов и целых fake теперь намеренно различается.** Целый fake
остаётся с клиентским кортежем и получает обычный kernel SNAT. Фрагментам
до подсчёта UDP checksum подставляется подтверждённая внешняя пара текущего
клиентского потока. Нельзя перевести fake вручную: ядро может принять его
за новое соединение и сменить порт. Нельзя оставить фрагментам частный адрес:
они обходят нормальный путь UDP conntrack. Границы объясняют
[разбор смещения фрагмента](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/netfilter/nf_conntrack_core.c)
и [проверка полной длины UDP](https://raw.githubusercontent.com/torvalds/linux/v6.12/net/netfilter/nf_conntrack_proto_udp.c).

Нет записи conntrack **или нет самого procfs-файла** → нет достоверной пары →
отказ до всех посылок и пропуск оригинала. Исключение «первый пакет, запись
ещё не подтверждена», допустимое для обычного sender, здесь НЕ применяется.
Это ограничение первого опыта, а не отрицательное свойство DPI.

## Что действительно проверено

- Red: parser отвергал все 4 формы; compose — 10 отказов; session — 32.
  После реализации соответствующие регрессии проходят.
- `test_quic_session`: все формы, с fake/без, TTL/TOS, целая checksum,
  ненулевые разные ID, порядок, короткий буфер, число wire frames сверх
  вместимости, отсутствие NAT-данных. Частичный опыт после первого фрагмента
  повреждён, оригинал нельзя отпустить; полного DONE нет.
- `check-fragment-plan-linux.sh`: реальный compose → TLV → session → raw →
  AF_PACKET capture на veth. Отдельный сервер в другом network namespace,
  настоящий SNAT с заменой порта, ответ возвращается исходному клиенту.
  Все 8 комбинаций совпадают по fragments/fakes/order. Посылки без перекрытий
  получают ответ; overlapping формы выходят точно, но этот Linux-сервер
  их не собирает. Успех этих форм не выдуман.
- Отказы `IP_NODEFRAG` и `SO_MARK` инъецированы только на системном вызове
  настоящего `raw.c`: 0 отправок, нет fallback на обычный сокет, повторная
  успешная настройка возможна.
- Общая арифметика builder повторно сверяется 96 случаями неизменённого Go.

Лаборатория запускается без внешней сети (`--network none`), без host-network
и privileged. NET_RAW/NET_ADMIN — для сокетов/собственного SNAT, SYS_ADMIN —
только для создания серверного network namespace внутри одноразового
контейнера. Образ с iptables/iproute2 строится отдельно из gcc:14.

**Границы доказательства:** вход результата измерителя в этой лаборатории —
структурная fixture, не заново выполненный поиск. Сервер — UDP echo с
проверкой исходного кортежа/данных, не QUIC/HTTP3. NAT реальный, но procfs
справка заменена hook на подтверждённую сервером пару (Docker может не
экспортировать этот procfs). NFQUEUE не удерживает настоящий оригинал:
проверены возвращаемый DROP и учёт подтверждений, не verdict в ядре.
Не путать это с полем или полной приёмкой приложения.

Попытка проверить SNAT на одном loopback namespace была непригодна: входящая
сторона попадала в conntrack того же «роутера» ещё раз и создавала коллизию
портов. Исправлен стенд, не ослаблен критерий: сервер вынесен за veth в
отдельное пространство, после чего ответы доходят исходному клиенту.

## Следующие обязательные действия

1. **Измерительный `qp_send_fragmented` пока НЕ получил NODEFRAG.** Предыдущий
   raw parity был без включённого conntrack. Воспроизвести этот эффект на
   исходном Go и C-измерителе с conntrack, сохранить вопросы/разрезы, отдельно
   обосновать нужную платформенную настройку. Не выдавать её отсутствие за
   «фрагменты не переживают линию».
2. Реальный NFQUEUE опыт для fragment-only/fake+frag: отсутствие целого
   оригинала на проводе, MTU/PMTU до всех отправок, частичный send failure,
   правильный ключ/поколение недоисполнения. Существующий MTU preflight в d2kd
   сохранён, но специального полевого/сетевого fragment MTU-опыта здесь нет.
3. Проверить доступность подтверждённой NAT-справки на целевом роутере и
   повтор после первого пропущенного пакета. Нельзя ради зелёной проверки
   разрешить фрагментацию с неизвестной внешней парой.
4. Далее прежний полный объём: UDP-протокольное доказательство, QUIC input и
   остальные вопросы Run, voice/nameless, коробки/перезапуск/деградация,
   серверный runtime C и сквозная приёмка. Зелёный Plan не закрывает MVP.
