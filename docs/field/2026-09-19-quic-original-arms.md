Продолжение после `9d8571d`, ветка `classify-core`; начальное дерево чистое.
Все изменения этой итерации — работа текущего исполнителя, не новые правки

Донор: `e9a391347671cbb07663d2bee5b3d92f016c789e`; текущий checkout
`bbd2edd769f47fa128e081d763c667be7e9de0b2` не меняет пакет quicprobe и три

## Что исправлено

1. `internal/quicprobe/arms.go:askArms` → `core/quicarms.c`.
   Пять оригинальных внутренних гипотез; затем копии 6/11, TTL 3/5/8/12,
   проверка выживания фрагментов и исходный порядок четырёх fragment-форм.
   Это внутренние данные прибора, НЕ пользовательский пул z2k и НЕ новый
   blockcheck. Три файла по 1200 байт встроены без изменения; default=620
   байт (0x40 и нули), последняя гипотеза — 16 нулей. Лицензия/происхождение
   сохранены в `THIRD_PARTY_NOTICES.md`.
2. `Run` → `core/quicprobe.c:d2k_quic_run`. Арсенал теперь вызывается ДО
   свойств; `addrPool.take` использует тот же pinned IP без residual и
   одноразовые запасные адреса при residual. Пул и бюджет не перезапускаются.
   Удалён дополнительный контроль на свежем IP, которого нет в оригинале.
   Диагноз content сохраняется при исчерпании пула; любой положительный
   residual-контроль допускает pinned-путь, как в исходнике.
3. `core/sched.c:worker_run` получает диагноз и приём одним вызовом.
   Отдельного позднего `d2k_sched_arm_hook` больше нет. Старый
   `d2k_quic_pick_arm` оставлен только для старых транспортных тестов,
   НЕ используется runtime и НЕ является образцом для продолжения.
4. Результат владеет найденными байтами. Scheduler/Plan больше не пересобирает
   их в «похожий» ClientHello. Копии не теряются при наличии TTL; если ось
   повторов ничего не дала, применяется исходный compose-default=2.
   Нет добавочной pace-паузы. Комбинация с пока невыразимыми фрагментами
   отвергается явно, а не превращается молча в fake-only.
5. Удалена выдуманная 60 мс пауза между fake и Initial в отправителе.
   На локальном состоянии приманки с временем жизни 40 мс исходный Go
   находил quic5/6/TTL3, а C выполнял 39 безуспешных опытов. Регрессия
   воспроизведена; после удаления паузы C совпадает с оригиналом.
6. Трасса арсенала сохраняет исходные названия, IP, отправки, ответы и
   отдельно причины «не измерено» (адреса/бюджет/локальный отказ).
   Scheduler выводит её; незавершённый поиск не выдаётся за полный отрицательный.
   Бюджет проверяется между вопросами. Потеря обходной метки в базовых
   измерениях делает найденный приём недостоверным — отдельный red→green тест.

## Доказательства и границы

Независимый стенд: `tests/quic-run/README.md`. Копирует неизменённый Go-пакет
во временный модуль, вызывает настоящие `Run`, `askArms`, `blobBytes`;
оба измерителя используют UDP-loopback. Сначала проверяется ожидаемый ответ
оригинала, затем сравнивается C. Linux запускает оба бинарника в контейнере
без внешней сети, raw-capabilities и записи в корень. Роутер не участвует.

- Все пять приманок совпадают побайтно.
- Одноадресный успешный арсенал: те же имя/копии/TTL, 9 зондов, порядок
  вопросов и трасса; искусственная 60 мс пауза обнаруживается стендом.
- Две residual-ветки полного Run: исчерпанный пул и частичный положительный
  контроль. Совпадают диагноз и арсенал; полная трасса свойств здесь НЕ сравнивается.
- Прежние шесть терминальных сценариев продолжают совпадать.
- C-тесты дополнительно покрывают fallback на default, вторую точку копий,
  поздний TTL, TTL-only/default copies=2, фрагментные ветки управления,
  неполный бюджет/пул, метку, порядок Run и точные байты плана в каталоге.

Финальная проверка: обе команды Go/C parity — код 0; полный
`make -C core -j4 check` — код 0; `make -C core cross` — код 0 (ARM64 musl
и MIPS glibc компилируются/линкуются, это не запуск MIPS-тестов).
Отдельные полные suites datapath/detect в этой итерации не перезапускались.

Команды воспроизведения:

```sh
D2K_REF_GO=/Users/mark/go/bin/go1.25.12 sh scripts/check-quic-run-parity.sh
D2K_REF_GO=/Users/mark/go/bin/go1.25.12 sh scripts/check-quic-run-parity.sh --linux
make -C core check

```

Санитайзеры: `test_quic_original_arms` и `test_quic_run_order` собраны из
исходников с `-fsanitize=address,undefined -fno-sanitize-recover=all`, код 0.
ASan этих тестов не означает ASan всего проекта.

Логи `/tmp/d2k-original-*-20260919.log`: `plan-red`, `gap-red`, `mark-red`
содержат реальные красные воспроизведения; `unit-final`, `parity-final`,
`linux-final`, `cross-final`, `sched-final`, `core-check-final` — проверки продолжения.

## Что исправлять следующим — не считать закрытым

1. **Точная IP-фрагментация оригинала.** `props.c:original_probe` пока
   возвращает not-measured для фрагментов: прежний raw hook делит по середине,
   а не pos8/overlap. Ветка управления перенесена, провод — НЕТ. Перенести
   `frag_linux.go`, проверить два/три фрагмента, позиции 8/32 и 16/48,
   overlap8, обратный порядок, IPv4/UDP checksum, владение mark/socket;
   затем выразить ровно эти формы в Plan и проверить fake+frag комбинации.
   Не включать старый midpoint-hook под новым названием.
2. **Остальной провод Run.** C меняет CID каждого повтора, но не создаёт
   заново все TLS-ключи/hello/нейтральное имя, как исходный buildInitial.
   Сверить таймауты (сейчас динамический минимум перекрывает тестовый wait),
   оставшуюся паузу перед residual, свойства/порядок/сборку всех вопросов,
   обработку отказов TTL sockopt. Нельзя называть локальную успешную сверку
   полного совпадением всех вопросов: такого доказательства пока нет.
3. **Вход клиента и подтверждение.** Сборка QUIC между датаграммами,
   поздний snapshot и не-AES профиль ещё открыты. Loopback-ответ —
   аутентифицированный Initial, не настоящий HTTP/3 и не успех приложения.
4. **Остальной MVP остаётся в чеклисте:** протокольное доказательство UDP,
   голосовой runtime через оригинальный поиск вместо фиксированного профиля,
   nameless IP-путь, переиспользование/деградация/восстановление коробок,
   web/runtime полностью на C, затем сквозная приёмка пользователя.
