# Поиск сдавался за двадцать плеч до нужного

Дата: 13.09.2026, вечер. Роутер владельца, живая линия.

## Цель, на которой это видно

`i.ytimg.com` — превью и каталог в приложении YouTube. Снято с провода
(tcpdump на `ppp0`):

```
Out  SYN                 → In  SYN-ACK  → Out  ACK      ← соединение встаёт
Out  seq 1:1401   (1400 байт)                           ← приветствие, часть 1
Out  seq 1401:1570 (169 байт)                           ← часть 2
     ... ни одного ответа. Клиент повторяет оба куска.
```

Коробка пропускает рукопожатие TCP и **молча глушит после приветствия**. Ни
сброса, ни ICMP. Блок по имени в чистом виде.

## Что сказал собственный замер d2k

```
вердикт: решает содержимое
  (разрез не помог (замерено без пауз между кусками),
   но контроль другим именем прошёл (3/3)
   — решает содержимое, ПОТОК ПЕРЕСОБИРАЕТСЯ)
```

**Коробка пересобирает поток.** Разрезом её не взять: она склеит куски и
прочитает имя целиком. Единственный ответ на такую коробку — перекрытие:
приставка, которую коробка примет за начало потока, а сервер отбросит как
уже полученное.

## Почему обход не находился

Перекрытия в запасном переборе есть — длиной 2, 4, 8, 16, 64, 336 и 681
байт. Но до них поиск не доходил НИ РАЗУ:

```
выведенные планы исчерпаны (зондов 22) — цель отдыхает
```

Посчитано: выразимых плеч в запасном переборе — **47**, бюджет зондов —
**21** (пять вопросов плюс два раза по восемь планов очереди). Тридцать одно
плечо не пробовалось никогда.

Потолок выводился из того, сколько планов влезает В ОЧЕРЕДЬ, а не из того,
сколько плеч вообще есть. Формулировка «выведенные планы исчерпаны» при этом
честная по букве и обманчивая по сути: кончились не плечи, а бюджет.

## Починка

Бюджет считается из самой лестницы:

```
пять вопросов дерева
+ восемь выведенных из вердикта кандидатов (не больше очереди)
+ ВЕСЬ запасной перебор (47, считается по таблицам)
= 60 зондов
```

Число не вписано, а берётся у `d2k_fallback_arms()`: список вырастет —
вырастет и бюджет. Отдельная проверка сверяет объявленное число с фактической
длиной списка перебором, а не повторением формулы: вторая копия арифметики
разошлась бы с первой молча.

**Почему это стало можно сделать только сейчас.** Раньше каждый зонд шёл за
счёт пользователя: пробный план вставал по имени и доставался всем
соединениям к цели (см. `2026-09-13-probe-pays.md`). Поднять бюджет означало
бы ломать цель дольше. Теперь пробный план виден только потоку зонда, и цена
поиска платится нашим трафиком, а не работой человека. Одна правка открыла
дорогу другой.

## Цена, названная прямо

Один зонд ждёт молчания до пяти секунд. Шестьдесят зондов на цель, молчащую
на всём, — до пяти минут поиска по одной цели. Одновременных задач до 64, но
каждый зонд это одно TLS-соединение: трафика мало, времени много.

## Чего это НЕ обещает

Что `i.ytimg.com` теперь возьмётся. Обещано ровно одно: поиск дойдёт до
перекрытий, а не остановится за двадцать плеч до них. Возьмётся или нет —
покажет замер после установки, и отрицательный ответ тоже будет ответом:
сегодня его не было вовсе.
