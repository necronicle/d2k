## Что воспроизведено и исправлено

1. **Чужой APPLIED подтверждал чужую цель.** У двух безымянных QUIC-целей
   одинаковый план имеет одинаковый plan_id. В T_VOICE_TRIAL код выбирал первую
   задачу только по ID/UDP; EXCHANGE второй цели записывал успех первой.
   Теперь адресный путь дополнительно проверяет IP и порт через существующий
   `applied_of_candidate`. Общий голосовой класс сохраняет прежнюю область.
   Тест: две цели с одинаковыми планами, ответы в обратном порядке, отдельный
   прогон с чужим портом, затем собственные ответы обеих целей.

2. **Адресная задача игнорировала дальнейшие подозрения.** Ранний return
   в on_suspect обходил разбор молчания своего потока и ветку WATCHING.
   Теперь адрес вычисляется как ключ перед общим жизненным циклом, а создание
   новой адресной задачи по-прежнему вызывает quic_addr_start.
   Тесты: чужое молчание не завершает опыт, собственное завершает; подозрение
   от потока без плана не прекращает наблюдение, от потока с планом позволяет
   выйти из наблюдения и запустить следующую попытку. Это восстановление
   существующего поведения, **не** доказательство полноценной политики
   деградации: один transient не должен означать подтверждённую потерю обхода.

3. **Очистка посылала DEL_NAME для IP-цели.** Адресная запись оставалась
   установлена после таймаута задачи. Добавлен `d2k_link_del_addr`: команда
   существующего протокола с четырьмя байтами IPv4; task_fail выбирает вид
   ключа. Тест читает настоящие кадры команд из socketpair, различает DEL_ADDR
   и DEL_NAME, проверяет адрес; таймаут подтверждённого WATCHING не снимает план.
   Доставка/ACK при обрыве управляющего соединения и изоляция поколений ещё
   не закрыты этими тестами.

4. **Cross-сборка пропускала зависимости нового QUIC-теста.** После добавления
   вызовов d2k_qc_first_initial host-рецепт получил quicconn/meas, а Linux-рецепты
   нет. Настоящий `make -C core cross` упал на undefined symbol. В обе cross-
   команды добавлены те же модули; повторная сборка/линковка прошла.

## Следующее действие — не потерять замысел

**Сначала ложное повышение UDP-ответа до успеха.** В datapath/session.c
обратная датаграмма после saw_hello/saw_initial порождает EXCHANGE без проверки
её содержимого; core/sched.c принимает это как voice_answered и сохраняет
level=3 через voice_confirm. Исправления выше лишь запрещают приписать этот
ответ другой IP-цели — они **не делают ответ протокольным доказательством**.
Нужны отрицательные тесты пустого UDP/мусора/неподходящего ответа и положительные
по действительно поддержанным QUIC/STUN/Discord-сценариям; сверить смысл
оригинальных исходов, не заменить их произвольным универсальным оракулом.

Далее проверить адресный путь: сейчас quic_addr_start устанавливает один
delay=15000, не вызывает оригинальный вопросник и не проверяет совместимые
найденные решения коробок. Отсутствие SNI — конкретный пробел входа, а не
основание заново изобретать весь инструмент. Также проверить, что любой
безымянный UDP не объявляется QUIC автоматически.

Проверка поколения/запоздавших событий, составного ключа (включая порт),
исключение проб на чужом трафике, восстановление после перезапуска и повторное
использование коробки остаются сквозными задачами. `d2k_sched_active` пока
не считает T_VOICE_TRIAL/T_VOICE_WATCH/T_TRIAL_SETTLE — это отдельный изъян
отчётности, а не доказательство отсутствия задач.

Пункт 5 MVP остаётся открытым. Наблюдение живого голоса и прежнее согласие
не ждать блокировки голоса не закрывают перечисленные дефекты доказательства.
