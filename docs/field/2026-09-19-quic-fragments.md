## Перенос, не новое поведение

| Оригинал | C | Свидетельство |
| --- | --- | --- |
| `frag.go:planCuts` | `core/ipfrag.c:d2k_ipfrag_cuts` | исходные позиции, округления, clamp перекрытий, короткие входы |
| `buildFragments`, `ipPacket`, `udpChecksum` | `d2k_udpfrag_build` | 96 сравнений точных байтов неизменённым Go |
| `frag_linux.go:exchangeFragmented` | `quicprobe.c:qp_send_fragmented` + общий цикл проверки AEAD | настоящие сокеты/AF_PACKET в Linux-лаборатории |
| `nextIPID` | `fragment_id` | случайное начало, счётчик под mutex, ненулевые разные ID повторов |
| `arms.go` четыре формы и нейтральный контроль | `props.c:original_probe` → `d2k_quic_fragment_hook` | красная регрессия подключения, затем зелёная |

Позиции считаются от **UDP-заголовка**, не QUIC payload. Исходные формы:
pos8; pos8 reverse; три фрагмента 8/32 с overlap8/8 reverse; три 16/48 с
overlap8/8 reverse. Clamp оригинала сохранён: у tiny первый overlap фактически
становится нулевым. UDP checksum считается до разрезания, IP checksum — для
каждого фрагмента, MF задаётся в логическом порядке до перестановки.

Публичная сборка ограничивает IPv4 payload, ёмкость выхода, известные flags
и требует ненулевой ID. Короткая датаграмма/нехватка буфера не дают частичного
выхода. Дополнительный отказ при ID=0 защищает от описанной самим оригиналом
перенумерации фрагментов ядром, не меняет ни одной допустимой исходной формы.

Старый `d2k_quic_build_frag2`/midpoint/raw-повторы остаются в legacy-тестах,
НЕ являются runtime и НЕ должны снова подключаться как «готовый аналог».

## Владение опытом и ограничения

Каждый повтор получает свой connected UDP socket и сохраняет его до завершения
проверки ответа. Нет close/rebind гонки. Повторы имеют собственные CID и IP ID;
ответ принимается общим существующим AEAD-проверщиком именно своего пакета.
CID обновляется прежней пересборкой C; полная свежесть TLS hello/ключей ещё
остаётся отдельным открытым переносом, её этот этап не объявляет сделанной.

Raw socket закрывается после отправки; receive sockets закрывает общий цикл.
Неполная отправка/нет raw capability/непригодный вход — локальный отказ,
не отрицательное свойство коробки. На macOS поведение исходного `frag_other.go`:
«не собрано/не измерено». Нет попыток угадать BSD raw-header semantics.

Осознанное отступление по SPEC §7: при отказе mark на receive **или raw**
сокете D2K не отправляет вообще, возвращает `marked=0` и `err`, а не измеряет
собственный обход. В оригинале EPERM/ENOPROTOOPT могут допускать непомеченную
отправку; для автоматического D2K-кандидата это недостоверно. Два теста отказа
подтверждают отсутствие фрагментов на настоящем проводе.

## Проверки

Финальный результат: полный core check, ARM64/MIPS cross, host/обычный Linux
parity и отдельный Linux raw capture — все с кодом 0. Кросс-сборка MIPS
означает компиляцию/линковку, не запуск на роутере. Полные suites
datapath/detect в этом этапе отдельно не перезапускались: их код не менялся.

```sh
make -C core -j4 check
make -C core cross
D2K_REF_GO=/Users/mark/go/bin/go1.25.12 sh scripts/check-quic-run-parity.sh
D2K_REF_GO=/Users/mark/go/bin/go1.25.12 sh scripts/check-quic-run-parity.sh --linux
D2K_REF_GO=/Users/mark/go/bin/go1.25.12 sh scripts/check-quic-run-parity.sh --linux-raw
```

Raw-режим — отдельный контейнер `--network none --read-only --cap-drop ALL
--cap-add NET_RAW`; нет внешних целей, роутера, privileged или host-network.
Это не тот же режим, что capability-free проверка «фрагменты не измерены».
Не смешивать их критерии.

Реальные результаты raw-лаборатории: pos8 и pos8 reverse — 3/3 ответов у Go
и C; обе overlap-формы — 0/3 у обоих на данном Linux-ядре. Это наблюдение
приёмника, не универсальное утверждение обо всех серверах. Захвачены все
фрагменты: совпадают с оригинальным `buildFragments` побайтно/по порядку;
три опыта имеют три порта, CID и ненулевых IP ID. При обоих отказах mark —
0 отправленных опытов и 0 захваченных фрагментов.

`test_ipfrag` прошёл ASan/UBSan. Это не sanitizer всей службы и не приёмка
HTTP/3: сервер отвечает аутентифицированным синтетическим Initial/CRYPTO.
Логи `/tmp/d2k-fragments-*-20260919.log`: `hook-red`, `hook-green`, `bytes`,
`raw-final`, `unprivileged`, `core-check`, `cross`. Первичная red-заглушка
сборщика дала 10 провалов до переноса арифметики; red подключения — один.
Финальная общая Go/C сверка — `host-final` и `linux-final`.

## Следующее действие: Plan, а не объявление MVP

**Находка fragment-only/fake+fragment пока не исполняется Plan.** Она честно
отвергается как невыразимая. Это существенный незакрытый участок: если оба
приёма найдены, нельзя молча выбросить fragment из комбинации или вернуть
старый midpoint. До выполнения следующего шага не выпускать этот checkpoint
как готовую полевую вертикаль/релиз MVP.

1. Перенести семантику `questions.go:compose`/`fragArmLine`: найденные fake
   и fragment комбинируются; после фрагментов целый оригинал гасится.
2. Расширить версионированный C Plan/TLV и исполнитель. Проверить все
   потребители: `core/compose.c`, `plantlv.c`, `datapath/plan_internal.h`,
   `plan_parse.c`, `plan_apply.c`, `wire_udp.c`, `session.c`, сборочные рецепты.
   Старый исполнитель должен отвергать новую операцию, а не игнорировать её.
3. Нынешний session запрещает несколько PAYLOAD для UDP, потому что это
   означало испорченные самостоятельные датаграммы. Отличить **IP-фрагменты
   одной** UDP-датаграммы от этой запрещённой подмены. Сохранить целую UDP
   checksum, общий ненулевой ID и конкретный порядок всех её фрагментов.
4. Измеритель уже имеет общий чистый builder `core/ipfrag.c` — не писать
   второй с иной арифметикой. Runtime использует действительный NAT-контекст,
   а не loopback адреса измерителя. Проверить исходные TTL/адреса/порты,
   MTU/вместимость, судьбу оригинала при полном и частичном исполнении.
5. Затем живые UDP-доказательства, остальной Run/input, voice/nameless,
   жизненный цикл коробок, C-web и сквозная приёмка — весь прежний объём ТЗ.
