# Этап G: установка проверена на чистой системе

Дата: 13.09.2026. Роутер НЕ ТРОГАЛСЯ ни разу.

`scripts/lab-install.sh` прогоняет шесть проверок этапа G в контейнере той же
арки, что и роутер Марка (aarch64): чистая установка, переход версии,
неудачное обновление, остановка, возврат в прежний режим, удаление.

Ставится при этом то, что лаборатория СОБРАЛА САМА из этого дерева, а не то,
что лежит в `builds/` неизвестно с какого прогона. Для этого у датапата
появилась нативная цель сборки (`make -C datapath d2kd`), а кросс-цели
переименованы в `d2kd-linux-arm64` / `d2kc-linux-arm64` — ровно те имена,
которые ищет `scripts/install.sh`. Прежние `d2kd-aarch64` не совпадали с
ожиданием установщика, и на живом роутере это выглядело бы как «не скачать».

## Что нашлось на первом же прогоне

**Установщик умирал на проверке арки, не сказав ни слова.** Строка

```sh
"$TMP/d2kc" >/dev/null 2>&1
[ $? = 2 ] || die "скачанный d2kc не запускается на этой системе"
```

при `set -e` (он стоит вверху файла) завершает установщик на ПЕРВОЙ строке:
`d2kc` без обязательного `--control` честно возвращает 2, и оболочка считает
это отказом команды. Вторая строка недостижима. На чистой системе установка
обрывалась после «загрузка», до подмены файлов, без объяснения.

Чинено: код снимается через `|| rc=$?` — в такой форме `set -e` не срабатывает.

Это ровно тот класс дефекта, ради которого этап G и существует: скрипт
читается как правильный, и только исполнение на чистой системе показывает,
что он не работал никогда.

## Что прошло

```
== 1. чистая установка ==      установлено и работает
== 2. переход версии ==        версия сменилась, конфигурация сохранена,
                               служба перезапущена
== 3. неудачное обновление ==  отказ до подмены: рабочая версия и правила
                               не тронуты
== 4. остановка ==
== 5. возврат в прежний режим == остановка и повторный запуск возвращают
                               систему в оба состояния
== 6. удаление ==              удалено без следов; каталог коробок удаляется
                               только по явному запросу
```

Проверки не на слово, а по фактам системы:

* работает ли служба — по `status` и по `/proc/<pid>`, а не по наличию
  pid-файла;
* сменилась ли версия — по sha256 установленного файла против sha256
  артефакта, причём артефакт пересобирается с другой оптимизацией, чтобы
  байты заведомо отличались;
* сохранена ли конфигурация — по метке, дописанной человеком до обновления;
* перезапустилась ли служба — по смене pid;
* неудачное обновление — испорченный артефакт: установщик обязан отказать
  ДО подмены, работающий процесс и правила остаются те же (сверка sha и pid);
* возврат в прежний режим и удаление — по ПОБАЙТНОМУ совпадению списка
  `iptables -t mangle -S` со снимком, снятым до установки.

## Что этим прогоном НЕ проверено

Названо прямо, потому что зелёный прогон легко принять за большее, чем он
есть. Контейнер даёт ту же арку, тот же netfilter и тот же
`start-stop-daemon`, но не даёт Entware, NDM и флеш-память роутера. Значит
остаются непроверенными:

* сброс правил силами NDM и хук `/opt/etc/ndm/netfilter.d/001-d2k.sh`
  (в контейнере каталога нет, установщик честно говорит об этом и ставит
  только периодического сторожа);
* переживание перезагрузки роутера;
* износ флешки и поведение при её отвале;
* установка на арке, отличной от arm64: тулчейна для остальных нет, и
  `scripts/build.sh` теперь отказывается собирать молча неполный набор.

## Чего ещё нет для однострочника

`curl … | sh` не публикуется, и причина не в осторожности: публиковать его
не с чего. `builds/` в репозиторий не коммитится (`.gitignore`), канала
выпуска у d2k нет — это отдельное решение (релизы GitHub, отдельная ветка
артефактов или что-то третье), и принимать его молча, задним числом, нельзя.

Пока рабочая и проверенная команда такая:

```sh
sh scripts/build.sh                                # три бинарника в builds/
D2K_LOCAL=<путь к дереву> sh scripts/install.sh    # на роутере
```
