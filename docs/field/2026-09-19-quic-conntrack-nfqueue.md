# QUIC: conntrack измерителя и настоящая NFQUEUE

База: `c63cb47c4a48efbaa5cff461da2e43886442942e`, ветка `classify-core`.
На старте рабочее дерево чистое. Эта передача относится к следующему коммиту;
старые ограничения [предыдущей передачи](2026-09-19-quic-fragment-plan.md)
сохранены как состояние именно того checkpoint, не текущего кода.

## Исправленный разрыв

Оригинал `quicprobe/frag_linux.go:exchangeFragmented` открывает raw IP-сокет
без NODEFRAG. C `core/quicprobe.c:qp_send_fragmented` воспроизводил это.
При активном Linux conntrack перестаёт исполняться исходная форма:
reverse отправляется прямым порядком, оба overlap локально теряются.
Побайтовый builder и прежний стенд без conntrack этого не показывали.

Новый `--linux-raw-conntrack` запускает неизменённый Go и C в изолированном
контейнере. Сначала воспроизведён красный C-тест: reverse wire mismatch,
ноль захваченных overlap-групп вместо трёх. Go показывает то же ограничение:
обычные формы отвечают 3/3, overlap — 0/3, reverse переставлен ядром.
После обязательного `IP_NODEFRAG` C сохраняет все четыре формы, заданные
исходным builder. Если настройка недоступна — ни одного фрагмента, sent=0,
результат «не измерено», не отрицательное свойство сети. Вопросы, порядок
перебора и сами формы не менялись. Это исправление воспроизведённого ограничения
транспорта оригинала, а не замена его алгоритма.

Донор не редактировался: текущий HEAD `10c6127b744bd3b8631bd381b20c496e06dc0423`,
проверяемый quicprobe и fake-файлы совпадают с pin
`e9a391347671cbb07663d2bee5b3d92f016c789e`.

## Исполнение через ядро

В `tests/fragment-plan` теперь есть второй проход: обычный UDP socket →
NFQUEUE → настоящий d2kd → raw/veth → отдельное серверное пространство → клиент.
Это fixture измеренного результата, не запуск всего поиска. QUIC Initial
настоящий, но сервер отвечает UDP echo, а не HTTP/3.

Убрана старая подмена NAT-hook: `/proc/net/nf_conntrack` доступен на стенде;
настоящий поиск записи и настоящий SNAT 54000→55000 проходят без неё.

| Опыт | Фрагменты | Приманки | Исходник | DONE | Ответ echo |
|---|---:|---:|---:|---:|---:|
| Формы 1/2, без fake | 2 | 0 | DROP | 1 | да |
| Формы 3/4, без fake | 3 | 0 | DROP | 1 | нет |
| Формы 1/2, с fake | 2 | 2 | DROP | 1 | да |
| Формы 3/4, с fake | 3 | 2 | DROP | 1 | нет |
| Предел MTU 1100, форма 2+fake | 0 | 0 | PASS | 0 | да |
| Отказ NODEFRAG, форма 2+fake | 0 | 0 | PASS | 0 | да |
| Отказ второй отправки фрагмента | 1 | 2 | DROP | 0 | нет |

Все захваченные фрагменты сверяются по полной длине/байтам/порядку с builder,
независимо проверенным 96 исходными Go-векторами. Частичная отправка даёт
«поток испорчен», исходник не просачивается. Отказ до первой отправки не
оставляет даже приманок. NODEFRAG/sendto faults подставляются только при
сборке test raw.o, runtime-продукт не читает переменные fault injection.

MTU здесь **явно заданный предел отправителя** через dummy interface;
настоящий маршрут остаётся 1500. Это не проверка изменения PMTU на маршруте.
NAT сначала подтверждён коротким seed-пакетом; холодный первый пакет не покрыт.
Ни контейнер, ни опыт не касались роутера или внешних сайтов.
